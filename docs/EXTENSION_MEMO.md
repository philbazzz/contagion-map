# 확장 설계 메모 — 금융기관 · 부동산 PF · 펀드 네트워크

MVP는 "노드 + 방향 있는 관계 + 라운드 단위 전파" 구조로 만들어, 산업이 바뀌어도 엔진과 화면을 그대로 쓸 수 있게 했습니다. 아래는 부동산 PF와 펀드·사모대출로 넓힐 때 필요한 변경입니다.

## 1. 데이터 모델 확장

### 노드 (`entity_type` 추가)
| 유형 | 예시 | 핵심 속성 |
|---|---|---|
| `project_spv` | PF 사업장 SPV / 시행사 | 총사업비, 분양률, 공정률, 준공 예정일, LTV |
| `contractor` | 시공사 | 자기자본, 우발채무 총액, 신용등급 |
| `trust_company` | 신탁사 (책임준공확약형 관리형토지신탁) | 자기자본, 책준 확약 잔액 |
| `securities_firm` | 증권사 (매입확약 · 주관) | 자기자본, 매입확약 잔액, NCR |
| `lender` | 은행 · 보험 · 캐피탈 · 저축은행 | 자기자본, 충당금 |
| `fund` | 부동산 펀드 · 블라인드 펀드 · 사모대출 | NAV, 차입, 환매 조건 |
| `vehicle` | PF-ABCP / ABSTB 유동화 SPC | 발행 잔액, 만기 |

### 관계 (`relationship_type` 추가)
| 유형 | 의미 | 충격 전달 방식 |
|---|---|---|
| `LOAN_TRANCHE` | 선순위 / 중순위 / 후순위 대출 | 담보 회수액을 **워터폴**로 배분 (후순위부터 손실) |
| `CREDIT_ENHANCEMENT` | 연대보증 · 채무인수 · 자금보충 · 책임준공 | 차주 부도 시 **우발채무가 실제 채무로 전환**되어 보강 제공자에게 전이 |
| `PURCHASE_COMMITMENT` | 증권사 ABCP 매입확약 | 차환 실패 시 매입 의무 발생 → 증권사 유동성 · 자본 충격 |
| `REFINANCING` | 브릿지론 → 본PF 전환 | 차환 실패 확률을 별도 변수로 |
| `FUND_LEVERAGE` | 펀드 레벨 차입 (현 MVP의 Fund A → Bank B와 동일) | 현행 로직 그대로 사용 |

## 2. 계산 엔진 확장

1. **담보가치 기반 회수율**: 고정 회수율 대신 `회수액 = min(채권액, 담보가치 × (1 − 할인율))`. 담보가치는 감정가 × 분양률 · 공정률 함수로 두고 사용자가 할인율을 조정.
2. **워터폴 배분**: 같은 차주의 여러 트랜치가 있으면 회수액을 선순위부터 채우고 남는 손실을 후순위부터 배분. 현재 `financial.py`의 한 라운드 처리 안에서 "차주별 회수액 풀"을 먼저 계산하는 단계를 추가하면 됩니다.
3. **우발채무 전환 라운드**: 차주 부도 → 같은 라운드에 `CREDIT_ENHANCEMENT` 엣지가 실제 익스포저로 활성화 → 보강 제공자(시공사 · 신탁사 · 증권사)의 자본에서 차감 → 임계치 미만이면 다음 라운드에 그 기관의 채권자로 전파. 국내 PF 위기에서 실제로 문제가 된 시공사 → 다른 사업장 연쇄 경로를 이 방식으로 표현할 수 있습니다.
4. **유동성 채널**: 자본잠식 외에 "만기 도래 차입 > 가용 유동성"이면 지급불능으로 보는 두 번째 부도 조건을 추가 (ABSTB 차환 실패 시나리오).
5. **부분 손실 계수**: 현재는 부도 시 손실 전액 인식. 확장 시 PD × LGD 기반 기대손실 모드를 별도로 두고, 부도 이벤트 모드와 구분해 표시.

## 3. 데이터 연결

- 저장소: `network.json` → PostgreSQL(노드 · 관계 테이블) + 시나리오 테이블. `service.load_network()`만 교체하면 엔진과 API는 그대로입니다.
- 내부 데이터: 대리금융기관 업무에서 관리하는 대주단 구성 · 트랜치 · 약정 잔액, 사업장별 분양률 · 공정률을 엑셀 템플릿으로 받아 일괄 업로드하는 기능을 우선 추천합니다.
- 외부 데이터: 금융감독원 전자공시(DART) 우발채무 주석, 신용평가사 PF 보고서, 시공사 신용공여 현황.
- 모든 숫자에 지금과 같이 `source_status`(VERIFIED / INFERRED / DEMO)와 출처 URL을 유지합니다.

## 4. 화면 확장

- 노드 색상 그룹에 `PF 사업장`, `시공사`, `신탁사`, `증권사` 추가 (`GROUP_COLORS`, `GROUP_DIRS` 두 곳만 수정).
- 관계선에 트랜치 순위 표시 (선순위 실선 · 중순위 점선 · 후순위 점점선).
- 우측 패널에 사업장 카드: 총사업비, 대주단 구성 표, 신용보강 구조도.
- 시나리오 비교: 같은 사업장에 대해 "분양률 −20%"와 "공사비 +15%" 두 시나리오의 결과를 나란히 보기.

## 5. 우선순위 제안

1. 워터폴 배분 + 담보가치 회수율 (PF 손실 계산의 기본)
2. 신용보강 전환 라운드 (시공사 · 증권사 연쇄 경로)
3. 엑셀 업로드
4. 유동성 부도 조건
